# Contributing

Thank you for your interest in contributing to Cognipeer open-source projects.

This is the default contributing guide for Cognipeer repositories that do not have their own. If a repository ships its own `CONTRIBUTING.md` or development docs, follow those first.

## Ways to contribute

- Report bugs and propose features using the issue forms.
- Ask questions in [Cognipeer Console Discussions](https://github.com/Cognipeer/console/discussions).
- Improve documentation, examples and tests.
- Fix bugs or implement agreed features through pull requests.

Do not report security vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).

## Pull requests

1. Open an issue first for larger changes so the approach can be agreed.
2. Fork the repository and branch from `main`.
3. Keep each pull request focused on one change.
4. Follow the existing code style and conventions of the repository.
5. Add or update tests and documentation for behavior changes.
6. Run the repository's lint, build and test scripts (see its `package.json` or README) before submitting.
7. Use clear, conventional commit messages, for example `fix: handle empty input` or `docs: clarify quick start`.
8. Describe what changed and why in the pull request description.

Maintainers review pull requests as time allows and may ask for changes.

## Code of Conduct

By participating you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
